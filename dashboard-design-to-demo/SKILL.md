# 设计稿还原 · V1.0

使用本次上传的设计图或 GIF 制作网页 Demo。一张清晰原图即可开始。首次成品以九成视觉观感为目标。在原稿大小和机位看，用户应当能认出同一个主体、同一处场景和同一组灯光。简单主体与可辨的二维元素应逐项吻合。复杂主体可保留需要近看才发现的细微差异。整体像素分数仅供定位问题。

## 先对准原稿中的主体

1. 读原始像素和 GIF 帧序。固定原稿画幅、镜头、示例数据和对照时刻。每张稿先选出两三处最能认出这张设计的细节，写下所在位置与可见特征。例如柱高的排列和悬浮卡遮住哪根柱子，地球上的海岸走向和山脊，厂区里塔口的形状、塔腰的暗点阵和相邻屋顶的遮挡。细节由本张原稿决定，多主体的图要覆盖各个主视觉。
2. 按原图搭出可操作画面。布局、文字、图表、数据标记及后加弹窗按原稿尺度和风格实现。可从本次原图提取头像、装饰或局部表面纹理，对倾斜表面先校正透视并分离大范围明暗。文字、数据图表、可操作控件与三维主体各自实现。点击图表与筛选项要能改变对应数据或详情。可绕看的主体从首屏起就使用同一套几何、材质与照明。
3. 在真实运行画面冻结原机位、曝光和动画时刻，保存整屏实拍。将原稿与实拍按同一坐标裁出所选部位，按实际大小直接看。再逐项检查其余可辨面板、数值和图表。轮廓不合先改模型比例、部件或镜头；表面不合再校正起伏、颗粒、反光和亮暗分布。修正后在原机位重拍同一部位，保留更接近原稿的版本。整页配色接近、按钮可点或镜头可以旋转，都不能抵消主视觉一眼可见的差异。
4. 为解决场景身份选对依据。原稿能辨认真实地理特征时，按相距较远的海岸、山脉等地标校准底图、起伏和镜头；可按素材规则采用有依据的地图或高程数据。随机生成的山脊只能用于原稿本身允许推定的区域。建筑与产品先按前、中、远景或部件关系还原轮廓、体积和空隙，再对照受光面、阴影落点与材质。单图可推定的常见结构直接补全，具体型号的识别特征按可见部分修改。

固定构图的界面默认将整幅设计按宽和高等比放入预览区。用户指定响应式排版时，按其目标尺寸分别对稿。用原稿尺寸和用户实际打开的窗口各看一次；工具有侧栏预览时实际缩窄窗口再测。看最右侧、底部和最窄面板：按钮应能点，表头按设计排列，主视觉不被意外挤窄。逐格核对有意义的照片或图像，优先从本次清晰原图裁取并随包提供。缺图标出对应格；空框、通用占位图及重复填图均计待修。

## 转到背面仍要成立

- 用户明确只要固定机位时按其要求制作。其余适合多角度查看的主体使用自然透视，提供拖动绕看、缩放和回到原稿机位。按主体和可用画布尺寸设置缩放范围，在原稿尺寸和窄预览里实做“放大、缩到主体完整可见、复位到原机位”。原稿刻意取局部特写时，复位回到该特写，缩远仍能看全。支持滚轮，并在宿主会截获滚轮或触屏手势受限时提供可点的缩放和复位控件。实际连续拖转一整圈，经过侧面、背面和交界再复位。观察厚度、接点、遮挡、阴影和标签位置；拉到最近与最远处，看建筑、道路和背景是否自然延展。补背面后复位看原机位。若已对齐的首屏退步，恢复已保存的较好版本，再局部修隐藏面。用户给出出错角度时，从两侧实拖经过同一角度并留下局部实拍。若目标是可旋转的三维，暂时只能实现固定视角时交阶段结果并标明缺项；改成固定视角成品由用户决定。
- 地球和连续曲面共用底色、凹凸与照明规则。用多个地标检查同一海岸或岛屿在球上只出现一次。对齐相同材质的底色、纹理尺度和起伏强度，以固定光源慢转接缝，掠射光下再看浮雕。圆柱同一高度的纹理应绕周接上，亮环和点阵随表面闭合。热图由同一高度或数据值驱动颜色、等值线和辉光。在背坡追踪同一色带，检查颗粒随坡面分布。原尺寸和目标大屏都看一处细线与暗部，兼顾清晰度和拖动流畅度。
- 车辆、设备等刚体先以单色模型察看宽度、体积、连接与接地，再用各自材质呈现玻璃、金属、车灯与轮毂。配置切换应改变对应部件，核对边界和遮挡。多视角 GIF 逐帧分辨绕转、换色和界面变化。对照相邻帧核对新机位的轮廓、开口和部件交接，换配置后再回原机位复看。隐藏面按同类构造、同种材料与灯光延展，特殊结构标明推定。
- 按含义补动效。地球默认缓慢自转，拖动时由用户接管。线路按数据方向流动，定位外晕呼吸，告警随事件位置脉动。动图优先遵循其实际节奏。检查静置、交互、整个循环和复位，数值、标签与部件正确关联；尊重减少动态效果的设置。

## 多稿顺序、阶段预览与暂停

开始时看一遍本次原稿，快速判断哪些可以直接实现，哪些涉及复杂建模或缺少依据。用户指定先看哪张，就从那张开始；否则先选能较快做完整、又能代表本次需求的一张。保留原稿编号与最终展示顺序。单张图优先完成原机位。

多稿先建一个试玩入口。第一张有可用内容就接入，逐张实点进入、返回；后续稿写状态，做好再接入。顺利完成并自查通过时，直接交成品。进入预计耗时较长的校准、等待额外资源或工具即将中断前，把已能看的版本和状态实际发给用户。进度正常且用户没有要求暂停时继续本次工作。平台只能在本轮结束时交文件的，就在本轮交出阶段结果，并说明如何续做。

**同一处连续两轮有针对性的修改，在相同机位或相同操作下都没有可见改善时，发出当前最好的可用版本，停在这一张，等待用户选择。** 每轮对应一个明确改动和一次实际复查；重复截图不算一轮。说明哪里仍有差距、试过什么，以及再试哪一种不同的办法最有希望。让用户选「继续修这里」「先做我指定的另一张」或「暂停项目」。收到选择后再安排后续，等待期间不自动切稿。只有一张时给出适用的选项。已知环境无法实现或实看该效果时，可直接说明，无需凑满两轮。

用户随时可以说「暂停」。收到后停止安排新操作，在最近一次已保存的可用版本上留下入口或可保存的源码、当前稿与待修部位，以及一句续做指令。例如「继续上次的地球，用同一机位检查背面的浮雕，保留已对齐的首页」。用户回来时，从该版本接着做。只陈述当前环境实际支持的保存、恢复和后台运行能力。需要跨对话或有临时链接时，能导出就同时给文件；只能输出文字时给可保存的代码和打开方法。

**验收始终以实际画面为准。** 有明确缺陷写「待修」，未能执行的检查写「待验证」，实际核对符合要求才写「通过」。阶段预览中明确能体验什么。若请求自由绕转、目前只做好首屏，原机位和绕看分别给结论。用户随后明确接受缩小范围，才按新范围判断成品，并记录其选择。

能写代码但无法预览时给可保存的网页或完整可运行代码、最短打开方法和未验项目。若连第一张完整页面都做不出，先返回已实现且能独立使用的部分，说明还缺什么。如果原图不可读或当前环境连有效代码也无法生成，立即说明阻碍和恢复所需的最小操作，例如将原图作为图片附件重发。仅在确有作用时才请求额外素材。下载地址、对比实拍与后台进度须有实际依据。

## 从用户拿到的入口验收

多张稿给**一个试玩入口**，一处即可选稿并返回。把这个入口放在交付消息最显眼的位置。能提供平台内试玩时，实际打开平台将展示的入口；提供本地文件时，从交付文件或最终 ZIP 的干净解压目录打开。有子页就逐个点击，检查页面、图表、图片和三维主体实际出现，再试关键交互及返回。链接应指向交付包中可找到的具体页面，例如 `earth/index.html`。用真实的打开方式复测，留意子页找不到、界面出现但画布空白，以及相对路径错误。

普通网页优先用能直接打开的交付方式。三维模块需要本地网页服务时，优先给该环境能直接打开的预览；交接到另一台电脑时，给可双击的自包含网页或适配目标环境的一键启动方式，写清必需的浏览器、运行环境及本地服务有效条件。用户实际接收的打开方式超出当前可验证范围时，写清已测哪一种、哪一种待验证。普通用户应能从同一入口找到所有作品。

正式交付附可试玩 Demo、可编辑源码、原图与同机位实拍，并简述残差。按张分别判断「原机位视觉」「绕看和交互」「交付入口」；只将实际检验且符合要求的项写成“通过”。对比实拍优先展示主体和关键局部。仍有明显落差的稿保留其最佳可用版本，列明实际状态与后续修法。开发交接另附静态包、依赖和打开方法，在空白网页宿主实开并操作最终包，写明验证到的导入方式。可辨读的数据按稿还原，推定数据与交互示例标明演示用途。

## 素材与随包工具

从零测试使用当批原稿、当次附带资料与通用工具，保留编号、像素和 GIF 帧序。普通项目拟复用历史模型、贴图或场景代码时，先说明来源与用途并取得同意。新用外部素材需核对授权并保留所需署名。历史截图仅在新结果完成后用于对照。遇到额外登录、付费、显著额度消耗或需将原图交给额外服务时，说明条件和本地可行方案，由用户选择。

以上正文可直接粘贴使用。安装环境可读随包文件时，三维场景开工先查适用的机位、材质与结构细则，交付前按视觉标准复查。仅粘贴正文时，直接按上文执行。正文中的同机位、绕看、阶段预览和打开入口规则适用于两种用法。

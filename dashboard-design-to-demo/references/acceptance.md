# 对稿与交接

## 浏览器里如何验收

先保存输入稿和原尺寸。固定浏览器视口、设备像素比、示例数据、字体、相机与动画时刻。直接截取运行画面。先按[逐项视觉验收标准](visual-standard.md)从原稿登记要对照的面板、图表、主体、机位和适用的空间／动效问题，再开始制作。每项记录参考、实际结果、可见差异和修正后的复测结果；无参考的隐藏面写明推定范围。

| 检查项 | 实际操作 | 通过条件 |
|---|---|---|
| 默认画面 | 原稿和浏览器画面同尺寸并排，再叠加；检查主体轮廓、主标题、面板边缘、文字基线、颜色与层次 | 画面主次、字号层级、主体占比、排布和清晰度与原稿一致。逐一复核各面板和图表。压缩、字体替代和模糊区域单独说明。 |
| 新增界面 | 同屏展示原稿中选作样板的组件与新弹窗或详情，测试打开、边缘位置和关闭 | 字体、行距、留白和装饰沿用原稿层级。尺寸适合内容，避开触发对象及重要信息；关闭后选中状态正确。 |
| 旋转与缩放 | 对适用主体实际拖动一整圈，取正、侧、背、顶关键帧；要求翻面时增加底视。放大检查后缩小、复位 | 旋转连续，细节和标记在各角度贴合主体；纹理接缝、材质突变、明显拉伸、空洞、穿插和镜头裁切需修复。复位画面回到原稿构图。 |
| 颜色与材料 | 逐个切换选项；在浅色、深色和高饱和颜色下放大边缘。旋转或缩放后复查，再恢复默认 | 应变部件完整覆盖，相邻部件边界清楚；受光、反射、纹理符合材质。检查漏色、越界、色边、残留旧色和遮罩错位。选项、名称与画面同步。 |
| 动效与数据 | 对照关键帧和完整循环；选择对象、替换样例数据、来回切换页面 | 节奏和层级与参考相符，动画结束或复位后状态正确；数值、点位、列表和详情的对应关系正确。 |

在原稿画幅和实际预览窗口执行同一组检查。固定大屏先看完整边界，然后核对最窄面板表头、底部图像及其对应内容。对可缩放主体，实际操作到能看见完整轮廓，再返回原稿机位。用滚轮以及项目实际提供的按钮或手势走一遍。多稿检查从统一入口逐项点击、体验并返回，尚未生成的稿明确显示状态。

需要自由旋转的项目，以实际拖动到任意中间角度并看到合理的轮廓、遮挡和材质变化为通过条件。动图回放、平面倾斜或少数预设角度只能记录为已实现的有限视角，完整旋转仍待完成。

可绕看的主体还须按[同机位对稿与反修](reference-view.md)分别判定原机位和透视绕看。为主体、身份特征和主要效果单独留同坐标近景，逐区记录“通过、待修或依据不足”。整图像素差用于定位偏差。清晰的设计几何、共享的背景素材和无法辨认的文字应分别说明。对高频纹理、阴影和动态效果，保留近景或操作录屏供设计方判断。

使用随包的图像比较脚本需要 Pillow。
```sh
python3 scripts/compare_frames.py design.png browser.png evidence/
```

要放大检查关键区域，可在同一命令后加 `--regions regions.json`。该文件用本次原稿像素坐标写出每个区域的左、上、右、下边界，右和下边界不包含在内。例如 `{"前灯":[120,65,155,98],"主阴影":[40,160,210,194]}`。每个区域按原始像素输出四栏，依次为原稿、实拍、半透明叠图、四倍放大的色差；区域名称和数值在 `metrics.json` 中。选区覆盖可见的特征整体，避免只取一小块单色样本。模糊或遮挡处单列说明，阈值只用于定位可见差异。

## 三维外观与速度如何验收

把浏览器操作结果和肉眼可见的结果分别记录。能旋转、换色、复位，说明对应操作可用。空间外观单独按下列适用项判断。

| 验什么 | 要留下的证据 | 判为待修的情形 |
|---|---|---|
| 核心结构 | 用单色模型从正面、侧面、背面和斜上方检查一次，再打开材质对原稿。保留最能说明厚度、开口和遮挡的一组图。 | 关闭照片后无法辨认主体，侧背面扁塌，轮子离地、部件重复、内外两层外壳同时可见。 |
| 连续表面 | 固定场景灯光，慢转一圈跨过纹理首尾与素材交界。停在接缝前、中、后，近看同一片区域。 | 同一种材质出现明显换色带，图案错位、拉伸，或绕回起点时跳变。 |
| 空间规律 | 追踪一条等高线或一圈塔身纹路，从原机位经斜侧转到背面，再回到起点。对有层厚的主体另取低侧视图。 | 色层随镜头移动，同层前后变色，侧面看不到应有的层厚，环带在背面形成 V 形、错层或中断。 |
| 部件与换色 | 从斜上方观察玻璃和框架，转过正前与正后，放大轮拱、车灯和车牌，再切浅色与高饱和色。检查连续转动录像，在原机位附近小幅来回拖动。 | 玻璃变成平黑块、车牌或格栅成双、同一车轮出现两层，或转动途中出现透明套壳。 |
| 轻量预览 | 在同一设备、浏览器、窗口大小和缓存条件下，记录冷启动到“主视觉已出现且可以拖动”的耗时、实际传输大小，以及沿同一路径连续拖动约 10 秒时的帧间隔和停顿。与改前版本或项目约定预算对照。 | 细节稍清楚却明显推迟首次操作，或转动持续掉帧。先精简不可见几何、复用材质，降低绘制开销或按需加载局部高清层，复测后再选择质量设置。 |

冷启动与拖动分别测量，注明真实设备还是软件渲染测试。只在导入环境、设备或时间目标明确时给相应的性能结论。没有性能实测时，将该项列为待测。单图背面只验结构和材料的合理性，精确实物还原需有对应视角的依据。

## 正式成品的内部签核

为本次输入逐张记录原稿身份、最终构建标识、已检视的实拍画面、主要局部、交互与多角度证据，以及每项结论。默认画面应先在原尺寸作第一眼并排判断，再看最能决定身份的局部。只记录实际看过或操作过的项目。对已认可的页面保留基线，检查回归。

能及时完成走查时直接交成品。预计继续修复耗时较长、已有修正未改善且缺少新办法或环境受限时，先交已保存的最好阶段预览。每张注明已实现、待修、待验证和可行的下一步。同一处连续两轮改动均无可见改善时，先发入口，停在当前稿，等待用户决定继续修、切换到指定稿或暂停。用户要求暂停时保留可用版本和续做指令。阶段预览与正式签核可独立进行。若有实质性依赖，向用户说清具体部位、已经试过什么，以及最少需要的素材或选择。用户确认的范围调整写回本次验收依据。正式导入包的结论由同一最终包的可视、可操作和导入实测共同决定。保留证据便于用户复核，不能让用户代做首轮验收。

## 交付前核查同一份成品

在内部目录构建候选包，从候选包启动独立宿主。保存一份 review.json，记录逐稿真实走查结论。每条结论保留具体观察，例如某个车灯的位置、绕到车尾时的衔接、换色后轮圈的边界。通过须由实际打开渲染结果、看过对比与旋转过程的人或执行模型判定。

验收记录格式沿用第 7 版，与 Skill 的公开版本单独编号。顶层写 `"standard":7`、候选包的 `package_sha256`、按原稿排列的 `cases` 和宿主结论 `host`。每例记录 `name`、原文件的 `reference_sha256` 及布尔值 `orbit`（绕看）、`variants`（多状态）、`animation`（连续动效，含新增呼吸动画）。多张视角参考共用同一模型时，每份输入仍有一份相应机位的对照。本轮重新计算原稿、证据及实测归档的指纹。从零测试重新制作并走查。

- `scope` 填清实际范围。以下键均为布尔值。`ui` 包含参照界面或图表，`extended` 含需延展的主视觉，`zoom` 可缩放，`relief_shading` 含需对照的浮雕明暗，`halo` 含定位或状态光晕，`data_terrain` 含数据地形或色层，`around_axis` 含环向需闭合的表面图案。另填布尔值 material_extension（需从原图补全连续表面）、display_detail（依靠细线、微粒或辉光表现细节）。以读稿清单、实际支持的操作和用户已指出的问题确定适用项。
- `panels` 逐条列出每块可见面板和其中每张独立图表，含唯一名称 `name`、结论、具体观察、局部对照证据。纯平面用同一清单列出页面和主组件。能看见的面板或图表还缺一项即为待修。
- `subjects` 逐条列出各延展主视觉，含唯一名称 `name`、结论、具体观察、同机位裁图证据和 `grades`。其中五个键照抄[评分表](visual-standard.md)的维度名称，每个值含 `grade` 和 `observation`。允许 `grade` 取“吻合”“细微”“待修”“依据不足”。有细微差异时写明具体部位和视角，另填可执行的 `refinement`。例如 `"光影与渐变":{"grade":"细微","observation":"斜前视角的引擎盖高光边缘略宽","refinement":"依据同角度局部近照收窄柔光源，复比高光轮廓"}`。每项实查达标则记录整体 `status` 为“通过”。
- `checks` 必填“默认机位”“关键局部”“主要交互”“加载与流畅度”。按 `orbit`、`variants`、`animation` 增加“连续绕看”“背侧与顶面”“精确复位”“状态或换色”“完整循环”。再按 `zoom`、`relief_shading`、`halo`、`data_terrain`、`around_axis` 分别增加“缩放边缘与场景延展”“浮雕明暗与细节”“光晕外观与状态”“背坡色层与纹理密度”“同高度周向闭合”。观察写清实际角度、缩放端点或关键帧及具体结果；附上能看到这些结果的连续操作或关键局部证据。

材质补全须另记“材质交界路径”，注明相机姿态及同一材料的对比部位；已知缺陷需复现反馈视角。依赖细节的主视觉须另记“展示尺寸与清晰度”，在记录的 samples 中为“原尺寸”“目标尺寸”各填一条实测记录，键为 view、css（宽高）、buffer（宽高）、dpr。两种尺寸相同时在同一尺寸检查真实目标设备像素比与局部，附分别命名的整帧和实际像素局部。数据地形另外补上同一特征的过脊侧面实拍。

宿主、局部和操作检查共用下面的记录格式。

```json
{"status":"待修","observation":"红色车身的漆色越过近侧灯罩边缘","evidence":[{"file":"captures/lamp-red.png","sha256":"填入实拍文件的 SHA-256"}]}
```

下列操作需给关键帧分别命名。在对应 `evidence` 条目加 `view`，每个状态用独立截取的 PNG、JPEG、WebP 或 AVIF。录像或接触表可作为附加证据。工具会检查各状态的文件指纹，避免一张首页截图签过多个角度。

| 检查 | 实拍关键帧的 `view` 值 |
|---|---|
| 缩放边缘与场景延展 | 最近、最远 |
| 背坡色层与纹理密度 | 原机位、过脊侧面、背坡低侧 |
| 材质交界路径 | 交界前、反馈或交界机位、交界后 |
| 展示尺寸与清晰度 | 原尺寸、目标尺寸 |
| 同高度周向闭合 | 缝前、缝上、缝后 |
| 连续绕看 | 原机位、侧面、背面 |

高度对称的对象可能在不同角度下外观相同，为对应实拍帧附上从运行相机读取的角度标注再存证。整圈仍要通过连续操作查看。多模式场景的每种模式都要核对，以能暴露原问题的一组端点帧签核，其余模式留附加证据。

把本次用户提供的全部原稿逐个传给检查脚本。脚本按实查评定核算每个主体的分数，校验各检查、证据指纹及实测包指纹，并输出需随成品说明的细微差异。脚本无法代看画面或替执行者识别漏填的物件，签核时要把清单与原图重新逐项勾对。硬性缺陷或无法检验的必查项保留“待修”或“依据不足”，修复后重拍受影响的证据。脚本通过后，可将实测的原 ZIP 标为正式验收通过。未通过时，随阶段预览点明失败项和下一步；已通过的独立稿可先从同一个入口打开。

```sh
python3 scripts/check_delivery.py review.json demo.zip design-01.jpg design-02.gif
```

## 导入与交接

将实际需要的运行文件列入 JSON 清单，生成包含 index.html 的静态包。用新的本地目录从最终 ZIP 导入；按目标宿主允许的子目录、嵌入和资源策略运行。

```sh
python3 scripts/pack_web.py web runtime-files.json dashboard.zip
python3 scripts/prepare_host.py dashboard.zip fresh-host
```

上述脚本需要 Python 3.9 或以上。按 prepare_host.py 输出的提示启动本机 HTTP 服务。走完主要操作，替换样例数据后在同一网址重新打开，并测试关闭与重开。记录包摘要、宿主、浏览器及实际验证范围。通用宿主通过时写“已验证标准 Web 同源嵌入”；客户指定平台通过时写明对应版本与验证结果。

## 复测 Skill 的通用性

有约定测试集时按项目约定复测，已获认可的场景作为回归基线。用户另给新图，或明确要求测试通用性时，用未参与规则制定的稿验证迁移能力。复用同样的读稿与验收方法，重新从每份稿提取设计参数。逐稿保留默认画面、至少一个关键操作状态、可见差异及素材限制，以实际结果判断稳定性。

需要验证重复生成是否稳定时，从已获准用于该项测试的新稿中选一张，在独立会话里只提供同一张图、同一条用户要求和这版 Skill，再生成一次。沿用相同视口和验收项比较两次结果，记录哪些细节或交互出现波动。

## 批次复测
以原图编号和 SHA-256 建立清单。批次报告 JSON 逐例记录适用范围 orbit、motion、variants，实拍文件及其指纹，具体观察和待修原因。inputs 标记当批原稿、当次提供的资料、通用工具或已获明确授权的既有项目资产。clean 模式拒绝既有项目资产。逐例通过检查后，从通过清单生成正式 ZIP，推荐目录 cases/编号/。用实际解压并在宿主启动过的同一 ZIP 运行批次核对。全部待修时省略 --release。对比图和试验入口永远标清状态。脚本校验文件身份、覆盖与归档，结论须来自逐项人工对图及浏览器操作。
```sh
python3 scripts/check_batch.py batch.json original-manifest.json --release release.zip
```

第 7 版验收记录的 scope 另登记 rigid、support、whole_surface。按适用项检验“刚体与附件”“支撑与连接”“背侧表面一致性”。有配置的项目为每组实际部件保存切换前后的不同实拍。动画保存同一动作的三个时刻。选项按钮与时间文字不计作部件差异。

普通项目在 batch.json 中记录 mode 为 project，每项既有项目资产的 consent 填写 approved、scope、user_message，以用户本次明确同意的范围为准。
